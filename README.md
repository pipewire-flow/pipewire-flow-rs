# pipewire-flow-rs

Rust bindings to [pipewire-flow], a C library that gives PipeWire
applications a simpler API for audio and video capture, audio playback, and
multi-port filters that bundle every input into one graph cycle.

| Crate | What it is |
| --- | --- |
| [`pipewire-flow-sys`](pipewire-flow-sys) | Raw FFI declarations, generated from the C headers by bindgen |
| [`pipewire-flow`](pipewire-flow) | The safe interface: owned handles, `Result`, and Rust closures for the C callbacks |

The bindings track C API 0.12.0, pinned as a submodule under `pipewire-flow-sys/vendor/`.

The two crates carry their own semver rather than the C library's, because a
change to the Rust interface and a change to the C API are different events and
each needs a version to say so. `pipewire-flow-sys` names the C release it binds
as build metadata, as in `0.2.0+pwf0.12.0`; that metadata is ignored when
resolving versions and is there to be read. Which C API a build actually got is
reported at runtime by `pipewire_flow::C_API_VERSION`, taken from the headers
themselves.

## Requirements

PipeWire is Linux-only, so the crates build and run there. Building needs
`libpipewire-0.3` >= 0.3.50 development files, and either `pipewire-flow`
>= 0.12.0 installed or the Meson toolchain to build the vendored copy.

An older installed `pipewire-flow` is not an error. pkg-config passes over it
and the build falls back to the vendored sources, saying so in a warning, so
check that warning if the library you meant to link against went unused.

```sh
sudo apt-get install meson ninja-build pkg-config libpipewire-0.3-dev libspa-0.2-dev
git clone --recurse-submodules https://github.com/pipewire-flow/pipewire-flow-rs
cargo build --features vendored
```

## Using it

```toml
[dependencies]
pipewire-flow = "0.2"
```

Capture from the default microphone for five seconds:

```rust,no_run
use pipewire_flow::{AudioConfig, Stream};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let stream = Stream::audio_capture(|buf| {
        if let Some(data) = buf.data() {
            println!("{} bytes (pts={:?} ns)", data.len(), buf.pts());
        }
    })?;

    stream.set_audio_config(&AudioConfig::new(48_000, 2))?;
    stream.start()?;
    std::thread::sleep(std::time::Duration::from_secs(5));
    stream.stop(false)?;
    Ok(())
}
```

Every callback runs on a thread the handle owns, so each closure is
`Send + 'static`, and the buffers it receives borrow the graph's memory for
one call only. Buffer callbacks run on the real-time data thread and must not
block. Dropping a `Stream` or `Filter` stops it and joins its threads.

## Examples

Each runs with `cargo run --example <name>`:

| Example | What it shows |
| --- | --- |
| `audio_capture` | Capture from the default audio source, stopping when the source is lost |
| `video_capture` | Capture 640x480 YUYV from the default camera |
| `audio_playback` | Play a 440 Hz tone to the default sink, or to one named on the command line |
| `list_targets` | Print every target a stream would accept, with each camera's formats |
| `filter_mix` | Mix two audio input ports into one audio output port |

## How the C library is found

`pipewire-flow-sys` probes `pkg-config` for an installed `pipewire-flow` first.
When that fails, or when the `vendored` feature is on, it builds the pinned
sources under `pipewire-flow-sys/vendor/pipewire-flow` with Meson and links them statically;
PipeWire itself still comes from the system either way.

Bindings are generated by bindgen at build time. Turning the default `bindgen`
feature off uses the copy committed at
`pipewire-flow-sys/src/bindings/pregenerated.rs` instead, which is also what
docs.rs builds against. To refresh that copy after a C API change:

```sh
PIPEWIRE_FLOW_SYS_UPDATE_BINDINGS=1 cargo build -p pipewire-flow-sys
```

On a machine with no PipeWire — macOS, say — the same works against the
submodule's own headers, which skips linking entirely:

```sh
PIPEWIRE_FLOW_SYS_HEADERS_ONLY=1 PIPEWIRE_FLOW_SYS_UPDATE_BINDINGS=1 \
  cargo build -p pipewire-flow-sys
```

Set that variable to a directory instead of `1` to read some other install's
headers. Either way the crate compiles but cannot be linked, so it is for
`cargo check` and for refreshing the committed bindings.

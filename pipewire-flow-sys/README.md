# pipewire-flow-sys

Raw FFI declarations for [pipewire-flow], a C library that gives PipeWire
applications a simpler API for audio and video capture, audio playback, and
multi-port filters that bundle every input into one graph cycle.

Everything here is generated from the C headers and is `unsafe` to call. Use
the [`pipewire-flow`](https://crates.io/crates/pipewire-flow) crate for a safe
interface; reach for this one only when you need something the safe layer
does not expose yet.

PipeWire is Linux-only, so this crate builds and runs there.

## How the C library is found

The build probes pkg-config for an installed `pipewire-flow` >= 0.12.0 first.
When that fails, or when the `vendored` feature is on, it builds the C
sources this crate ships under `vendor/` with Meson and links them
statically. PipeWire itself comes from the system either way, so
`libpipewire-0.3` >= 0.3.50 development files are needed regardless.

Bindings are generated by bindgen at build time. Turning the default
`bindgen` feature off uses the copy committed at
`src/bindings/pregenerated.rs`, which is also what docs.rs builds against.

## Versioning

The crate carries its own semver, and names the C release it ships as build
metadata: `0.2.0+pwf0.12.0` binds pipewire-flow 0.12.0. That metadata is ignored
when resolving versions, so the crate version itself moves whenever the
pinned C release does.
